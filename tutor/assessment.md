# 성숙도 판정

## 수준

네 수준을 쓴다(go-develop과 같은 틀, CS2023 숙련 수준에서 왔다). Explain이 나머지의 선행 수준이다. 영업에서의 증거로 적는다.

| 수준 | 이름 | 증거 |
|---|---|---|
| 0 | 미접촉 | 없음 |
| 1 | Explain | 자기 말로 설명하고, 왜 그런지 말한다(예: 왜 이 딜이 이 단계에 있으면 안 되는지) |
| 2 | Apply | 처음 보는 딜·고객 상황에서 직접 해내고, 결과를 예측한다(예: 디스커버리 질문을 짜고 답을 예상한다) |
| 3 | Evaluate | 선택지를 비교해 근거와 함께 결정한다(예: 할인과 조건 교환 중 무엇을 줄지) |
| 4 | Develop | 실제 제약 안에서 쓸 수 있는 산출물을 만들어 낸다(예: 자기 딜의 제안서) |

## 증거의 무게

- 자기 신고는 어디부터 물어볼지 정하는 데만 쓴다. 숙달의 근거가 아니다.
- 탐침과 과제의 결과만 수준을 올린다.
- 정의를 외워 답한 것은 증거가 아니다. 튜터가 방금 준 힌트를 학습자가 되받아 말한 것도 증거가 아니다(빈틈을 해결됨으로 바꾸려면 힌트 없이 새 상황에서 한 번 더 해내야 한다). 프레임워크 글자(MEDDIC의 M·E·D…)를 말하는 것도 증거가 아니다.
- 경력·연차·실적은 자기 신고와 같다. 「10년 했어요」는 어디부터 물을지만 정한다. 감으로 맞힌 결론과 근거를 댄 결론을 구분한다. 결론이 맞아도 근거가 「경험상」뿐이면 부분 정답이다.

## 탐침 만드는 법

- 그 모듈의 목표 수준에 맞춘다. 정의를 묻지 않고 처음 보는 딜 상황(고객 한마디, 파이프라인 숫자, 제안서 한 줄)에서 예측·판단·진단하게 한다. 학습자의 실제 상품·고객이 있으면 그것으로 만든다.
- 힌트를 주지 않고 짧게 답할 수 있게 낸다. 탐침은 예측·진단·수정 중 하나만 묻는다. 덧붙일 수 있는 것은 「이유」 하나뿐이다. 원인과 고치는 법은 다음 차례로 나눈다. 페이지 조작을 부탁한 차례에는 새 문제를 내지 않는다.
- 판정 기준을 내기 전에 정한다. 결론만 맞고 이유가 틀리면 맞음이 아니다.

## 판정 절차

모듈당 탐침은 최대 3개, 판정까지 3차례를 넘기지 않는다.

| 결과 | 경로 | 기록 |
|---|---|---|
| 목표 수준 탐침 2개 정답(입구 진단에서 그 모듈을 직접 다룬 정답도 1개로 센다) | 건너뜀. 한 줄로 알리고 다음으로 | `status: verified_skip`, 달성 수준, 증거 |
| 하나 정답, 하나 부분 정답 | 빈틈만 다룬다 | `status: in_progress`, `gaps`에 빈틈 |
| 첫 탐침 오답이나 「모르겠어요」 | 한 단계 낮춰 다시 묻거나 전체 경로로 | `status: in_progress` |
| 학습자가 그냥 넘어가겠다고 함 | 바로 넘어간다. 돌아올 수 있다고만 말한다 | `status: self_skip`, 증거 없음 |
| 그 외(정답과 오답, 부분 정답 둘 등) | 빈틈만 다룬다 | `status: in_progress`, `gaps`에 빈틈 |
| 학습자가 「처음 본다」고 함 | 탐침을 생략하고 풀이 예시부터 보여 준다 | `status: in_progress`, 시작 수준 0 |

- 「다 알아요」는 사실 진술이므로 강의하지 않고 곧바로 목표 수준 탐침을 낸다. 「건너뛰죠」는 결정이므로 바로 `self_skip`으로 넘어간다. 둘이 함께 나오면 결정을 따른다.
- 학습자가 시간을 쓰겠다고 말한 모듈은 탐침을 맞혀도 자동으로 건너뛰지 않고, 건너뛸지 더 깊이 볼지 묻는다.
- 목표가 Develop인 모듈(`curriculum/map.md`에서 목표가 Develop인 것, 졸업 프로젝트 X 전부)은 짧은 탐침으로 건너뛰지 않는다. 학습자가 이미 만든 실제 산출물(진단표·제안서 등)을 함께 검토해서만 건너뛴다.
- `self_skip`과 `estimated`는 숙달이 아니다. 그 모듈이 선수인 모듈을 시작할 때 핵심을 탐침 1개로 확인한다.
- 탐침에서 드러난 빈틈이 다른 모듈에 속하면 `gaps`에 기록하고, 지금 흐름에 필요한 만큼만 메운다.

## 영역 빠른 확인

학습자가 영역 전체를 빠르게 확인하고 싶어 하면, 뒤쪽의 심화 모듈부터 탐침한다. `verified_skip`이 된 모듈의 선수 모듈(다른 영역의 선수도 포함, 직접 선수만)을 `inferred`로 기록하고 다시 묻지 않는다. 탐침 1개만 맞은 `estimated` 모듈로는 추론하지 않는다. 튜터도 입구 진단 뒤에 이 확인을 먼저 제안할 수 있다.

## 복습 간격

인출 연습과 분산 학습이 학습 기법 중 효용이 가장 높게 평가되었으므로(Dunlosky 외, 2013) 복습을 넣는다.

- 완료 시 `review_step: 0`, `review_at`은 1일 뒤로 둔다.
- 복습에 성공하면 간격을 3일, 7일, 21일로 늘린다. 21일 복습에도 성공하면 `review_at`을 `null`로 둔다.
- 실패하면 `review_step`을 0으로 돌리고 빈틈을 `gaps`에 적는다.
- 복습은 세션 시작 시 1개만 낸다. 새로운 상황으로 바꿔 묻는다.
- `verified_skip`은 복습 대상이 아니다.

## 기록 형식

`learner/state.json`의 `modules`에 모듈 id를 키로 둔다.

```json
"P2": {
  "level": 2,
  "status": "done",
  "evidence": ["2026-11-14 가상 파이프라인 전환율 진단 — 답: \"제안→계약은 괜찮은데 미팅→제안에서 반이 죽어요, 자격 심사가 없어서\""],
  "review_at": "2026-11-15",
  "review_step": 0
}
```

`status`는 `estimated`, `inferred`, `in_progress`, `done`, `verified_skip`, `self_skip` 중 하나다. `inferred`는 상위 모듈을 통과해 추론한 것으로 다시 탐침하지 않는다.

출제와 채점을 튜터 혼자 하므로, `evidence`에는 판단만 적지 않고 **학습자의 답을 짧게 인용한다.** 따옴표 안은 대화에서 그대로 복사한다. 구절을 잇거나 조사·어미를 바꾸지 않고, 줄일 때는 `…`를 쓴다. 바꿔 쓰려면 따옴표 밖 요약으로 쓴다. 따옴표 기호만은 JSON 안에서 「」로 바꿔도 된다(그 밖의 글자·문장부호는 바꾸지 않는다). `gaps` 문구 안에 따옴표로 인용할 때도 같은 규칙이고, 요약은 따옴표 밖에 쓴다. 예외 하나 더: 실제 고객사명·사람 이름·연락처는 인용 안에서도 `[고객사A]`, `[담당자]`처럼 대괄호 가명으로 바꾼다. 학습 기록에 실명을 남기지 않는다.
